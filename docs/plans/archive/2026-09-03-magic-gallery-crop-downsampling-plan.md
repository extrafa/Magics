# Полноразмерная перерисовка в viewDidLoad и сохранение без даунсемплинга — план

Task spec: ревью uamoder. `MagicGalleryCropViewController.viewDidLoad()` зовёт
`sourceImage.bakingOrientation()` синхронно на main thread — полная
перерисовка кадра через `UIGraphicsImageRenderer` (для 4032x3024 это ~48 МБ
несжатого битмапа). Кадр с основной камеры всегда приходит с
`imageOrientation == .right`, так что guard `!= .up` не спасает — перерисовка
происходит всегда, с заметной паузой между спуском затвора и экраном кропа.
Дальше `extractCrop()` вырезает область в исходных пикселях (~3000x3000),
`saveCustomPhoto` кодирует это в JPEG без ограничения стороны — то, что потом
хранится на диске и перечитывается в память, крупнее, чем реально нужно
(карточка 184pt + полноэкранный показ, где хватает ~2000px).

## Решение (два независимых изменения из (в))

1. Нормализация ориентации уходит с main thread — считается один раз в фоне,
   ДО показа `MagicGalleryCropViewController`, а не внутри его `viewDidLoad`.
2. Итоговый кроп перед сохранением ограничивается по стороне (~2000px) —
   через `UIImage.preparingThumbnail(of:)`, тем же приёмом, что уже
   используется для превью сетки.

## Чанк 1 — MagicGalleryPhotoLibrary.swift

`saveCustomPhoto`: перед JPEG-кодированием — `resized(image, maxSide: 2000)`
(даунсемпл только если сторона реально больше, апскейл не нужен). Хелпер —
`nonisolated static`, рядом с уже существующим `thumbnail(of:)`.

## Чанк 2 — MagicGalleryCropView.swift

- Убрать `bakingOrientation()` и свойство `normalizedImage` — кроп-контроллер
  получает уже нормализованное изображение снаружи, работает напрямую с
  `sourceImage` (в `setupScrollView()` и `extractCrop()`).
- `viewDidLoad()` больше не делает перерисовку — только фон.

## Чанк 3 — MagicGalleryCameraView.swift

- После выбора кадра в пикере — нормализация ориентации в фоне
  (`Task.detached`, тот же паттерн, что уже используется в
  `MagicGalleryPhotoLibrary`), затем `pendingImage` выставляется уже
  нормализованным.
- Пока идёт нормализация — короткий лоадер (чёрный фон + `ProgressView`)
  вместо текущего эффекта «завис экран», это и есть суть фикса перфоманса.
- Функция нормализации — `extension UIImage`, доступна из этого файла (была
  `private` внутри `MagicGalleryCropView.swift`).

## Чанк 4 — сборка + живая проверка

Снять/выбрать фото через Photo Library в симуляторе (камера в симуляторе не
даёт реального кадра), убедиться что кроп-экран открывается без фриза с
коротким лоадером, подтвердить кропнутое фото сохраняется и по размеру не
крупнее ~2000px по стороне (лог/проверка `image.size` до отправки в PR).
