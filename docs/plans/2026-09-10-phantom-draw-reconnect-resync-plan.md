# PhantomDraw: надёжный реконнект без раскрытия трюка зрителю

## Позиция по ревью (оспорим в комменте о выполнении)

Ревью предлагает при обрыве показывать на «передающем» телефоне (роль `.sender`,
телефон зрителя) экран потери связи / «переподключаемся» и завести состояние
`.reconnecting`. Для этого трюка так делать нельзя: зритель рисует именно на
sender-устройстве, и любой UI про подключение устройств, коды, «ищем маг() —
раскрывает механику трюка. Холст на sender при обрыве обязан оставаться холстом.

Что действительно является проблемой (и что чинит этот план):
- убедиться, что при переподключении на телефон фокусника доезжают ВСЕ линии,
  нарисованные зрителем за время обрыва;
- дать фокуснику способ вспомнить код для переподключения, если он случайно
  выкинул приложение.

## 1. Долив линий при переподключении

### Как сейчас (по коду — работает)

- `PhantomDrawViewModel.commitStroke()` делает `completedStrokes.append(stroke)`
  безусловно, ещё до `session.send`. То есть линии, нарисованные во время
  обрыва (когда `connection == nil` и `send` тихо выходит), всё равно копятся.
- `activateIncomingConnection(_:)` на новом коннекте: сперва `connection = conn`
  (стр. 202), затем в `.ready` → `onNewConnection?()`.
- `onNewConnection` (задан в `PhantomDrawViewModel.init`) у роли `.sender`
  шлёт `session.send(.sync(completedStrokes))` — весь массив целиком.
- Приёмник в `receiveLoop` на `.sync(all)` делает `receivedStrokes = all`
  (замена целиком, не добавление).
- Листенер sender'а не гасится при обрыве (только `teardown()`), а
  `newConnectionHandler` пропускает новый коннект, пока `isReconnecting == true`.

Итог: после реконнекта фокусник получает полный актуальный набор линий. Это
проверено по коду, ручной тест это подтвердит.

### Единственная дыра — очистка «в пустоту» во время обрыва

Сценарий: зритель порисовал → обрыв → зритель нажал «очистить»
(`completedStrokes = []`, `send(.clear)` ушёл в никуда) → реконнект. Гард
`!self.completedStrokes.isEmpty` в `onNewConnection` не пускает `.sync`, и на
приёмнике остаются старые линии.

Правка (1 строка): убрать `!self.completedStrokes.isEmpty` из гарда
`onNewConnection` в `PhantomDrawViewModel`. Тогда реконнект донесёт `.sync([])`
и приёмник очистится. Пустой `.sync` на приёмнике безопасен —
`receivedStrokes = []`.

## 2. Sender при обрыве — `connectionState` НЕ трогаем

Ничего не меняем в `activateIncomingConnection` ветке `.failed/.cancelled`
(остаётся `connection = nil` + `isReconnecting = true`). `connectionState`
остаётся `.connected(peerName:)`, `isSenderCanvas` остаётся `true`, холст на
месте, кнопки выхода нет, зритель ничего не замечает. Это осознанное решение,
а не баг.

## 3. Подсказка с последним кодом — механизм переподключения фокусника

### Как сейчас

`PhantomDrawView` держит `@AppStorage("phantomDrawLastCode") codeInput` —
одно свойство, которое одновременно и биндинг `TextField`, и персист. Введённый
код автоматически предзаполняет поле при повторном заходе.

### Что меняем

1. Убираем автоподстановку кода в поле. `codeInput` становится обычным
   `@State var codeInput = ""` — поле всегда пустое при заходе.
2. Заводим отдельный персист `@AppStorage("phantomDrawLastCode") lastCode`,
   который пишется при УСПЕШНОМ подключении receiver'а (переход в `.connected`)
   и читается только для подсказки, не для поля.
3. Добавляем вторичный текст «Last connection code: XX» — по нему фокусник
   вручную вводит код и переподключается к трюку, если что-то произошло
   (случайно закрыл приложение и т.п.).

Матрица — при каких `PhantomDrawConnectionState` показывать подсказку:

| Состояние | Экран | Подсказка |
|---|---|---|
| `.idle` | выбор роли | НЕ показываем — этот экран видит и зритель, код на нём светить нельзя |
| `.enteringCode` | ввод кода (receiver-only, зритель сюда не попадает) | показываем «Last connection code: XX», если `lastCode` непустой; если пустой — ничего (заглушку не рисуем) |
| `.searching` | поиск | без изменений (у sender — крупный код в `searchingView`, у receiver — ничего) |
| `.connected` | холст / приёмник | ничего |
| `.failed` | «Could Not Connect» | ничего |

Итог по UI: одна новая `Text` в `enteringCodeView` (`PhantomDrawView.swift`),
завёрнутая в `if !lastCode.isEmpty`.

### Про случай «зритель сам закрыл приложение»

Отдельно ничего не делаем. Если холст (sender) отваливается, девайс фокусника
это явно видит и сам уходит на экран подключения — это не проблема и трюк не
портит, просто нужно переподключить устройства. `startAsSender()` при этом
сгенерирует новый код — это ок.

## Чанки

1. `PhantomDrawViewModel`: убрать `!self.completedStrokes.isEmpty` из гарда
   `onNewConnection`. Сборка + тесты.
2. `PhantomDrawView`: `codeInput` → обычный `@State`; завести отдельный
   `@AppStorage("phantomDrawLastCode") lastCode`, писать его при переходе
   receiver'а в `.connected`. Сборка.
3. Локализация: добавить ключ `phantomDraw.lastCodeHint`
   (`Last connection code: %@`) в `Localizable.xcstrings` (все локали).
4. `PhantomDrawView.enteringCodeView`: добавить `Text` с последним кодом,
   видима только при непустом `lastCode`. Сборка.
5. Ручная проверка на двух устройствах:
   - подключиться, порисовать N линий;
   - на приёмнике убить приложение;
   - на sender дорисовать ещё M линий (холст не мигнул, кнопки выхода нет);
   - на приёмнике перезайти receiver'ом → поле пустое, под ним подсказка
     «Last connection code: XX» → ввести код вручную → переподключиться;
   - на приёмнике появляются все N+M линий;
   - отдельно: перед реконнектом на sender нажать «очистить» → после реконнекта
     приёмник пустой.
